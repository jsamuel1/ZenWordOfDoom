# v0.4 Accessibility Compliance — Design

**Date:** 2026-07-02
**Status:** Approved design (full-sweep scope, user-selected)
**Branch:** `feat/v0.4-accessibility` (worktree, based on `main` @ a88056a)
**Source:** 2026-07-02 accessibility audit of `App/ZenWordOfDoom/` against WCAG 2.2 AA and
Apple HIG/Accessibility guidance. Finding numbers below (1.1–6.10) refer to that audit.

## Problem

The audit found four blockers — VoiceOver can reach and activate the "hidden" gameplay
controls behind the LevelClear/DoomExpired overlays (2.3); the play screen's fixed
380pt grid + 240pt wheel can push Submit off-screen at accessibility text sizes with no
scroll fallback (1.5); dark-mode wheel tiles render white-on-white at ~1:1 contrast
(3.1); solved crossword letters are green-on-green at ~1.8:1 (3.2) — plus ~7 serious
and ~20 moderate/minor findings. **Scope: the full sweep — every audit finding.** The
grid gets the "summary + per-slot values" VoiceOver treatment. Verification adds an
XCUITest accessibility audit and contrast/scaling unit tests.

## Constraints

- No gameplay behavior, scoring, or generation changes; determinism untouched.
- Art direction preserved: scrims are subtle by default and strengthen only under the
  relevant accessibility settings or where contrast is otherwise unprovable.
- No new user-facing settings — respond to the system settings (Dynamic Type, Reduce
  Motion, Reduce Transparency, Increase Contrast, VoiceOver, Button Shapes).
- Existing good patterns (audit inventory) are the templates: `.combine` rows,
  `CutSceneView`'s reduce-motion timeline, `.sheet()` modality, 56pt wheel targets.

## 1. Dynamic Type & reflow (findings 1.1–1.6)

- **Play screen reflow (1.5, blocker):** wrap `GamePlayView`'s main `VStack` in a
  `ScrollView` so nothing becomes unreachable as type grows. The reveal stays a
  full-screen background (outside the scroll). Verify at AX5 on an SE-class simulator.
- **Menu reflow (1.6):** `ScrollView` around `MenuView`'s content; `Spacer()`s become
  fixed padding inside the scroll.
- **Scaled tiles (1.1, 1.2):** `WheelView.tileSize` and `WordRibbonView`'s tile size /
  ribbon height become `@ScaledMetric(relativeTo:)` values with a 44pt floor on wheel
  tiles (touch target) and sane caps so a 9-tile wheel still fits; wheel `radius`
  derives from the scaled size. Letters get `.lineLimit(1)` + `minimumScaleFactor` as a
  belt-and-braces inside the now-scaling frames.
- **Grid letters (1.3):** `minimumScaleFactor` 0.5 → 0.8 in `GridView`; the grid's
  height cap participates in the new scroll layout so cells can occupy more height on
  large-type layouts rather than crushing the glyphs.
- **Fixed fonts (1.4):** `MenuView`'s 44/32pt title and `LevelClearView`'s 44pt score
  move to Dynamic-Type-participating styles (`.system(size:weight:design:)` →
  text styles or `relativeTo:`-scaled custom metrics).

## 2. VoiceOver (findings 2.1–2.8)

- **Modal containment (2.3, blocker):** the gameplay `VStack` gets
  `.accessibilityHidden(...)` mirroring its existing opacity/hit-testing guards when
  `LevelClearView` or `DoomExpiredOverlay` is shown. VoiceOver focus moves to the
  overlay when it appears (2.8) via `@AccessibilityFocusState` on its heading.
- **Real announcements (2.2):** a small `Announcer` seam (protocol + default posting
  `AccessibilityNotification.Announcement`; Null implementation for tests) invoked by
  `GameViewModel` at each meaningful `lastMessage` event: word found, bonus, invalid,
  hint reveal, doom expiry, level clear. The `.updatesFrequently` trait stays on the
  message line for polling.
- **Timer urgency (2.7, 6.6):** announcements (and the existing haptic vocabulary) at
  30s / 15s / 5s remaining in doom mode, driven from `tickTimer()` threshold crossings.
- **Grid state (2.1) — summary + per-slot values:** `GridView` becomes an accessibility
  container labeled `"Crossword grid, X of Y words solved"`. Each slot is one
  accessibility element: `"5-letter word, across — solved: STONE"` or
  `"4-letter word, down — S, blank, O, blank"` (revealed cells read in order). Slot
  elements are not interactive; play remains via wheel/voice.
- **Wheel VoiceOver path (2.6):** each `TileView` gains
  `.accessibilityAction(.default)` invoking `onTap(tile.id)` plus
  `.accessibilityRespondsToUserInteraction(true)`, guaranteeing activation regardless
  of the parent `DragGesture(minimumDistance: 0)`; Submit/Clear/Shuffle already reach
  VoiceOver as buttons. A manual Accessibility Inspector verification item is recorded
  in the checklist (see §5).
- **Rows and images (2.4, 2.5):** `BestiaryView` rows get `.combine` + explicit label
  with the thumbnail hidden (mirroring `StatsView.row`); `MenuView`'s backdrop image
  gets `.accessibilityHidden(true)`.

## 3. Contrast & color (findings 3.1–3.7)

One new file, `App/ZenWordOfDoom/AccessibilityPalette.swift`, holds the fixed,
documented color pairs (with their computed ratios in comments) so unit tests can pin
them (§5):

- **Wheel tiles (3.1, blocker):** unselected tile letters use a fixed dark foreground
  (`Color(white: 0.12)`) on the fixed near-white tile — scheme-independent, ≥ 12:1.
  Selected-tile pair verified ≥ 4.5:1 against `accentColor` or given a fixed pair.
- **Solved grid letters (3.2, blocker):** fixed dark green (target ≈ `#1B6B2A`-class,
  exact value chosen to clear 4.5:1 against the `green.opacity(0.18)`-tinted white
  cell).
- **Unfilled cells (3.3):** opacity raised and a 1pt stroke added; the grid container
  gains a scrim so cell boundaries hold ≥3:1 regardless of scene art.
- **Text over imagery (3.4, 3.5, 3.6, 3.7):** MenuView title/serenity/daily-card text
  sits on a strengthened scrim block; the HUD capsule gets a fixed-opacity dark backing
  independent of stir; `LevelClearView` gains the same black scrim
  `DoomExpiredOverlay` already has; `WordRibbonView`'s placeholder rises to a
  compliant opacity on a scrim.

## 4. Touch targets & system settings (findings 4.1–4.4, 5.3, 6.1–6.3)

- **44pt floors (4.1–4.4):** HUD hint/mic buttons framed to ≥44×44; play controls and
  the two overlay Continue buttons get `.controlSize(.large)`; store price buttons get
  `minHeight: 44`. (Wheel tiles already 56pt — floor preserved under scaling, §1.)
- **Reduce Transparency (6.1):** a shared `View` modifier —
  `a11yCardBackground(cornerRadius:)` — renders `.ultraThinMaterial` normally and an
  opaque fill when `accessibilityReduceTransparency` is on. Applied at all seven
  audited sites (grid, HUD, LevelClear card, DoomExpired card, bonus capsule, pack
  banner, daily card).
- **Increase Contrast (6.2):** `AccessibilityPalette` exposes
  `colorSchemeContrast`-aware variants for the marginal pairs (unfilled cell, HUD
  secondary text, solved green darkens further).
- **Button Shapes (6.3):** plain-styled tappable rows (shrine, level select, serenity
  link, daily card) get a subtle always-on border affordance (cheaper and more robust
  than runtime `buttonShapesEnabled` checks, and visually consistent).
- **Mic pulse (5.3):** `.symbolEffect(.pulse, isActive: isListening && !reduceMotion)`.

## 5. Verification

- **Unit tests (`ZenWordOfDoomTests`, the existing app test target):**
  `WCAGContrastTests` computes WCAG relative-luminance contrast for every pair in
  `AccessibilityPalette` (resolved via `UIColor`) and asserts ≥4.5:1 for text pairs,
  ≥3:1 for UI-component pairs — the palette can never silently regress. Scaled-metric
  floors (wheel tile ≥44) asserted where resolvable.
- **UI test target (`ZenWordOfDoomUITests`, new in project.yml):** iOS 17's
  `performAccessibilityAudit()` on the menu, level select, play screen, and settings
  (launching into a level via the existing app flow), filtered to the audit types we
  can hold stable (`.dynamicType, .contrast, .elementDetection, .hitRegion`). Wired
  into the scheme's test action; CI-runnable.
- **Manual checklist:** `docs/ACCESSIBILITY.md` — the shipped conformance notes plus a
  short release checklist: VoiceOver wheel-tile activation (2.6), AX5-on-SE reflow
  pass, Reduce Transparency visual pass, Accessibility Inspector audit. Also records
  the audit inventory of already-good patterns so they're preserved.
- Standard gates: `swift test`, `xcodebuild test` (unit + UI), review subagent per
  task, final whole-branch review.

## 6. Out of scope

- Full per-cell explore-by-touch grid (summary + per-slot chosen instead).
- Custom rotor / keyboard-navigation work beyond what SwiftUI provides.
- Localization of accessibility strings (English only today, matching the app).
- Audio-description of cut-scene poems (already text, already read by VoiceOver).
